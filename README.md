# AI Interview Prep

![CI](https://github.com/Shovan05/AI-Powered-Interview-Preparation-Platform/actions/workflows/ci.yml/badge.svg)

AI-powered interview preparation platform that analyzes your resume and a target job description to generate a personalized match score, technical & behavioral interview questions, skill gap analysis, and a day-wise preparation roadmap. Also generates a tailored, ATS-friendly resume PDF for the job.

**Live demo:** [ai-interview-prep-mu-five.vercel.app](https://ai-interview-prep-mu-five.vercel.app)
> The backend runs on Render's free tier and sleeps after inactivity, so the first request can take about a minute.

## Features

- 🔐 **Authentication**: JWT (cookie-based) auth with register/login/logout; users are stored in PostgreSQL with bcrypt-hashed passwords and a case-insensitive unique email; logged-out tokens are blacklisted in Redis with a TTL (MongoDB fallback when Redis is not configured)
- 📄 **Resume Parsing**: Upload a PDF resume (parsed with `pdf-parse`) or provide a quick self-description instead
- 🤖 **AI-Generated Interview Report**: Powered by Google Gemini, returns:
  - Match score (0–100) against the job description
  - Technical questions with interviewer intention + model answers
  - Behavioral questions with interviewer intention + model answers
  - Skill gap analysis with severity levels
  - Day-wise preparation roadmap with focus areas and tasks
- 📥 **Tailored Resume PDF**: Generates a job-specific, ATS-friendly resume as a downloadable PDF (via Puppeteer)
- 🗂️ **Report History**: View all previously generated interview reports
- 🛡️ **Rate Limiting**: Redis-backed limits on login/register (10 per 15 min per IP) and on report/PDF generation (10 per hour per user)
- ⚡ **Caching**: Redis cache-aside caching for reports and report history, invalidated when a new report is created
- 🧵 **Background Jobs**: Interview reports are generated by a BullMQ worker with retries, while the API returns immediately and the frontend polls for the result
- 🗄️ **Two databases, each for what it fits**: relational user data in PostgreSQL (with SQL migrations), JSON-heavy AI reports in MongoDB
- 📘 **API Documentation**: Interactive OpenAPI docs with Swagger UI at /api-docs

## Tech Stack

**Frontend**

- React 19 + Vite
- React Router v7
- Axios
- Sass (SCSS)

**Backend**

- Node.js + Express 5
- TypeScript
- PostgreSQL (`pg` driver, plain SQL migrations) for users and authentication
- MongoDB + Mongoose for interview reports
- JWT (`jsonwebtoken`) + `bcryptjs` for authentication
- Multer for file uploads
- `pdf-parse` for resume text extraction
- Google Gemini (`@google/genai`) for AI generation
- Zod + `zod-to-json-schema` for structured AI response schemas
- Puppeteer for HTML-to-PDF resume generation
- Jest + Supertest + `mongodb-memory-server` and a PostgreSQL test database for integration tests
- Redis (ioredis) for the token blacklist with TTL
- BullMQ (Redis-backed job queue)
- OpenAPI 3 + Swagger UI (swagger-ui-express)

## Getting Started

### Prerequisites

- Node.js (v18+ recommended)
- Docker (the easiest way to run PostgreSQL and Redis locally)
- A MongoDB instance (local or [MongoDB Atlas](https://www.mongodb.com/atlas))
- A Google Gemini API key ([Google AI Studio](https://aistudio.google.com/))

### 1. Clone the repo

```bash
git clone https://github.com/Shovan05/AI-Powered-Interview-Preparation-Platform.git
cd AI-Powered-Interview-Preparation-Platform
```

### 2. Start PostgreSQL (and optionally Redis)

Put a password for the database in a `.env` file in the repo root (next to `docker-compose.yml`):

```
POSTGRES_PASSWORD=choose_a_local_password
```

Then start the containers:

```bash
docker compose up -d postgres redis
```

The Postgres container is published on host port **5433**, because port 5432 is often already used by a PostgreSQL installed on your machine.

### 3. Backend setup

```bash
cd Backend
npm install
```

> `npm install` also downloads Chromium for Puppeteer (used for PDF generation), so the first install can take a few minutes.

Create a `.env` file in `Backend/`:

```
MONGO_URI=your_mongodb_connection_string
DATABASE_URL=postgresql://app:choose_a_local_password@127.0.0.1:5433/interviewprep
JWT_SECRET=your_jwt_secret
GOOGLE_GENAI_API_KEY=your_gemini_api_key
```

Run the backend:

```bash
npm run dev      # development: tsx with auto-restart
npm run build    # compile TypeScript to dist/
npm start        # run the compiled build
npm run migrate  # apply pending SQL migrations without starting the server
```

The server applies any pending migrations automatically at startup and runs on `http://localhost:3000`.

### 4. Frontend setup

```bash
cd Frontend
npm install
```

Create a `.env` file in `Frontend/`:

```
VITE_API_URL=http://localhost:3000
```

Run the frontend:

```bash
npm run dev
```

The app runs on `http://localhost:5173`.

### Environment variables

| Variable | Where | Required | Purpose |
| --- | --- | --- | --- |
| `MONGO_URI` | Backend | Yes | MongoDB connection string (interview reports) |
| `DATABASE_URL` | Backend | Yes | PostgreSQL connection string (users), e.g. `postgresql://app:PASSWORD@127.0.0.1:5433/interviewprep` |
| `DATABASE_SSL` | Backend | No | Set to `true` if the hosted PostgreSQL requires SSL |
| `JWT_SECRET` | Backend | Yes | Secret used to sign auth tokens |
| `GOOGLE_GENAI_API_KEY` | Backend | Yes | Google Gemini API key |
| `PORT` | Backend | No | Server port (defaults to `3000`) |
| `REDIS_URL` | Backend | No | Redis connection string. If unset, the API runs without Redis and stores blacklisted tokens in MongoDB |
| `TEST_DATABASE_URL` | Backend (tests, CI) | For tests | PostgreSQL test database. The database name must contain `_test` |
| `POSTGRES_PASSWORD` | Repo root `.env` | For Docker | Password of the PostgreSQL container in Docker Compose |
| `VITE_API_URL` | Frontend | Yes | Base URL of the backend API |

## Run with Docker

Create a `.env` file in the repo root (next to `docker-compose.yml`):

```
POSTGRES_PASSWORD=choose_a_local_password
JWT_SECRET=your_jwt_secret
GOOGLE_GENAI_API_KEY=your_gemini_api_key
```

Then run:

```bash
docker compose up --build
```

This starts the API on `http://localhost:3000` together with local MongoDB, Redis and PostgreSQL containers, so no Atlas account or separate installs are needed. Compose sets `MONGO_URI`, `REDIS_URL` and `DATABASE_URL` for the API automatically. The API waits until PostgreSQL is healthy and then applies any pending migrations from `Backend/migrations`.

## Database migrations

PostgreSQL schema changes are plain SQL files in `Backend/migrations`. They are applied in filename order, once each, inside a transaction, and recorded in a `schema_migrations` table. To change the schema, add a new numbered file (for example `002_add_something.sql`) and never edit a file that has already been applied.

## Running Tests

First create the PostgreSQL test database once (the Postgres container must be running):

```bash
docker compose exec postgres psql -U app -d interviewprep -c "CREATE DATABASE interviewprep_test;"
```

Add this line to `Backend/.env`:

```
TEST_DATABASE_URL=postgresql://app:choose_a_local_password@127.0.0.1:5433/interviewprep_test
```

Then run:

```bash
cd Backend
npm test               # run all tests
npm run test:coverage  # run with a coverage report
npm run lint           # ESLint
```

Tests use an in-memory MongoDB for reports and the PostgreSQL test database for users, which is emptied between tests (the name must contain `_test`, so the tests refuse to run against any other database). Test files run one at a time because they share that database. The first run downloads a MongoDB binary, which can take a few minutes. CI runs the same tests against a PostgreSQL service container.

## Deployment

The frontend is deployed on Vercel, the backend on Render (Node web service) and PostgreSQL on Render's managed Postgres.

Render settings:

| Setting | Value |
| --- | --- |
| Root Directory | `Backend` |
| Build Command | `npm install --include=dev && npx puppeteer browsers install chrome && npm run build` |
| Start Command | `npm start` |
| Environment | `MONGO_URI`, `DATABASE_URL`, `JWT_SECRET`, `GOOGLE_GENAI_API_KEY` (do not set `NODE_ENV`; add `DATABASE_SSL=true` only if the database connection requires SSL) |

Notes:

- The build runs `tsc`, which is a dev dependency, so `--include=dev` makes sure it installs regardless of `NODE_ENV`.
- `Backend/puppeteer.config.cjs` keeps Chrome inside the project folder, and the build installs it explicitly, so it is available at runtime for PDF generation.
- Use the database's **Internal Database URL** for `DATABASE_URL` when the web service is in the same Render region.
- Migrations run automatically when the server starts.
- On Vercel, set `VITE_API_URL` to the Render service URL.

## Troubleshooting

**`querySrv ECONNREFUSED` when the backend connects to MongoDB Atlas**

- Free Atlas clusters pause after a period of inactivity. Open Atlas and resume the cluster, then restart the backend (it only tries to connect once at startup).
- Some networks (campus, office, some routers) cannot resolve the SRV records Atlas uses. In development the server uses public DNS servers to work around this; if you still see the error, try another network or use the non-SRV (`mongodb://`) connection string from Atlas.

**`password authentication failed for user "app"` for PostgreSQL**

- Another PostgreSQL server (for example one installed on Windows) may be using port 5432, so your connection reaches it instead of the Docker container. Use the container's published port `5433` in `DATABASE_URL`.
- The `POSTGRES_PASSWORD` is only applied when the data volume is first created. To change it later, run `ALTER USER app PASSWORD 'new_password';` inside the container (`docker compose exec postgres psql -U app -d interviewprep`) and update your `.env` files to match.

**Login or any API call returns `404` in development**

- `Frontend/.env` is missing or `VITE_API_URL` is wrong. Create it as shown above and restart the frontend (Vite reads `.env` only at startup).

**`npm install` fails while downloading Chromium**

- Delete `node_modules` and the Puppeteer cache (`~/.cache/puppeteer`), then reinstall. To skip the download for now, set `PUPPETEER_SKIP_DOWNLOAD=true`. Resume PDF generation will not work until Chromium is installed (`npx puppeteer browsers install chrome`).

**`Could not find Chrome` when generating a resume PDF on Render**

- Chrome was not installed into the folder Puppeteer looks in. Make sure the build command includes `npx puppeteer browsers install chrome`, then run Manual Deploy with "Clear build cache & deploy".
